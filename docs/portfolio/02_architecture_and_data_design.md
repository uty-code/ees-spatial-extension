# [Portfolio] 02. 시스템 아키텍처 및 데이터 모델링 설계

본 프로젝트는 고도의 정합성이 요구되는 인사 평가 시스템의 특성을 고려하여, **계층화된 관심사의 분리(Separation of Concerns)**와 **강력한 데이터 무결성 보장**을 최우선 과제로 설계되었습니다.

## 1. 시스템 아키텍처 (Layered Architecture)

표준화된 4계층 아키텍처를 채택하여 각 레이어의 책임을 명확히 분리하고 유지보수성을 극대화했습니다.

*   **Presentation Layer (Controller)**: 요청 검증 및 응답 처리를 담당합니다.
*   **Business Logic Layer (Service & ServiceImpl)**: 핵심 평가 로직 및 유효성 검증을 수행하며, 트랜잭션의 경계가 됩니다.
*   **Data Access Layer (Mapper/MyBatis)**: SQL 쿼리와 도메인 객체를 매핑하며, 복잡한 통계 쿼리를 직접 제어합니다.
*   **Infrastructure Layer**: Security, Audit, Database 등 공통 기술 서비스를 제공합니다.

## 2. 데이터 모델링 및 정합성 전략

### 핵심 엔티티 및 스냅샷 관리
*   **Frozen Snapshot 전략**: 평가 매핑(EvaluatorMapping) 생성 시점의 조직 정보를 테이블에 비정규화(Denormalization)하여 저장합니다. 
    *   **설계 근거**: 인사 정보 변동에 관계없이 과거 평가의 불변성을 확보하는 것이 저장 공간의 오버헤드보다 비즈니스적으로 더 중요하다고 판단했습니다. 대용량 데이터 환경에 대비하여 `period_id` 기반의 인덱스 설계를 통해 조회 성능 저하를 방지했습니다.

### 데이터 무결성 정책 (Common Policy)
*   **Soft Delete & Filtered Index**: `is_deleted` 컬럼을 통한 논리 삭제를 수행하되, MSSQL의 **필터링 인덱스(Filtered Index)**를 활용하여 활성 데이터에 대해서만 Unique 제약 조건을 보장함으로써 운영상의 데이터 중복 문제를 해결했습니다.
*   **공통 감사(Common Audit) 및 폴백**: `SecurityUtil`을 통해 수정자를 자동 기록하되, 스케줄러나 배치 작업처럼 인증 컨텍스트가 없는 환경에서는 'SYSTEM' ID로 자동 기록되는 폴백 로직을 구현하여 데이터 추적성을 유지했습니다.
*   **Locking Strategy**: 동시 입력이 잦은 로직에 **비관적 락(Pessimistic Lock)**을 적용하고, DB 타임아웃 설정을 통해 커넥션 점유 시간을 제어하여 시스템 가용성을 확보했습니다.

## 3. 아키텍처적 차별점 및 검증

### 가상 스레드와 리소스 조율
가상 스레드 도입으로 증가한 동시 요청이 한정된 DB 커넥션 풀(HikariCP)을 고갈시키지 않도록 튜닝했습니다. 
*   **검증 방식**: `CountDownLatch`를 활용한 동시성 유닛 테스트를 통해, 수백 개의 가상 스레드가 동시에 DB에 접근할 때 데드락 없이 안정적으로 처리되는지 수치로 확인했습니다.

### 보안 계층의 분리 (AOP 기반 인가)
비즈니스 로직의 순수성을 지키기 위해 Spring Security의 `@PreAuthorize`를 활용한 선언적 인가 시스템을 구축했습니다. 이를 통해 권한 제어 로직의 변경이 비즈니스 코드에 영향을 주지 않도록 격리했습니다.

---

## 💡 설계 회고
설계 과정에서 가장 중요하게 생각한 것은 **'성능(가상 스레드)'과 '정합성(비관적 락)' 사이의 트레이드 오프**를 관리하는 것이었습니다. 무조건적인 기술 도입보다, 실제 발생 가능한 예외 상황(배치 작업의 감사 로그, 락 대기 시간 등)을 사전에 시뮬레이션하고 테스트 코드로 검증하는 과정이 시스템의 신뢰도를 결정한다는 소중한 교훈을 얻었습니다.
