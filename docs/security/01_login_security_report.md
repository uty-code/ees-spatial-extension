# [Security Report] 로그인 비밀번호 노출 위험 분석 및 대응 전략

## 1. 개요 (Executive Summary)
웹 브라우저(Chrome, Edge 등)에서 로그인 시 발생하는 "비밀번호 노출 위험" 경고는 단순한 알림이 아니라, 현재 웹 사이트가 현대적인 보안 표준(Security Best Practices)을 충족하지 못하고 있음을 나타내는 지표입니다. 본 보고서는 이 경고의 발생 원인을 기술적으로 분석하고, 서비스 신뢰도 확보를 위한 단계별 해결 방안을 제시합니다.

## 2. 원인 분석 (Root Cause Analysis)

### A. 전송 계층 보안(TLS/SSL) 부재
*   **현상**: `http://` 프로토콜을 사용하는 환경에서 비밀번호를 전송할 때 발생.
*   **기술적 이유**: HTTP는 데이터를 평문(Plain Text)으로 전송하므로, 동일 네트워크상의 공격자가 '패킷 스니핑'을 통해 비밀번호를 쉽게 가로챌 수 있습니다. 브라우저는 이를 감지하여 사용자의 입력 데이터가 위험에 노출되었음을 경고합니다.

### B. 취약하거나 유출된 비밀번호 사용
*   **현상**: "이미 유출된 데이터베이스에 포함된 비밀번호입니다"라는 구체적인 경고 발생.
*   **기술적 이유**: 구글과 같은 브라우저 제공업체는 수십억 개의 유출된 비밀번호 해시 DB를 보유하고 있습니다. 사용자가 입력한 해시값이 이 DB와 일치할 경우, 해당 계정의 탈취 위험이 매우 높다고 판단하여 경고를 띄웁니다.

### C. 자동완성 및 폼 속성(Autocomplete) 관련
*   **기술적 이유**: `<form>` 태그에 `action` 속성이 명시되지 않거나, 보안이 취약한 주소로 데이터를 보낼 때 브라우저의 휴리스틱 보안 엔진이 경고를 유발할 수 있습니다.

## 3. 기술적 해결 방안 (Technical Solutions)

### 단계 1: 전송 구간 암호화 (HTTPS 적용)
가장 근본적이고 필수적인 해결책입니다.
*   **SSL/TLS 인증서 도입**: Let's Encrypt(무료) 또는 유료 CA를 통해 인증서를 발급받아 서버에 적용합니다.
*   **HSTS(HTTP Strict Transport Security) 설정**: 브라우저가 항상 HTTPS로만 접속하도록 강제하는 보안 헤더를 추가합니다.
*   **Spring Boot 설정 예시**:
    ```yaml
    server:
      ssl:
        enabled: true
        key-store: classpath:keystore.p12
        key-store-password: your_password
        key-store-type: PKCS12
    ```

### 단계 2: 비밀번호 저장 및 검증 정책 강화
*   **강력한 해시 알고리즘**: 현재 적용된 `BCrypt`는 'Salt'와 'Work Factor'를 지원하여 무차별 대입 공격(Brute-force)을 방어하는 최적의 선택입니다.
*   **복잡도 검증 로직**: 
    - 최소 8자 이상, 대소문자, 숫자, 특수문자 조합 강제.
    - `Have I Been Pwned` API 등을 연동하여 유출된 비밀번호 등록을 사전에 차단.

### 단계 3: 현대적 보안 헤더 적용 (Spring Security 활용)
*   **X-Frame-Options**: 클릭재킹 방어.
*   **X-Content-Type-Options**: MIME 스니핑 방어.
*   **Content-Security-Policy (CSP)**: XSS 공격 방어 및 신뢰할 수 있는 소스에서만 스크립트 실행 허용.

## 4. 포트폴리오 활용 전략
이 문제를 해결한 과정은 면접에서 **"사용자 경험과 보안 사이의 트레이드 오프를 어떻게 관리했는가?"**라는 질문에 대한 훌륭한 답변이 됩니다.

*   **Action**: "단순히 경고를 무시하는 것이 아니라, SSL 인증서 적용 및 전송 구간 암호화를 통해 보안 표준을 준수하도록 인프라와 백엔드 로직을 개선함."
*   **Result**: "브라우저 보안 경고 제거 및 데이터 전송 구간에서의 중간자 공격 위험 원천 차단."

## 5. 결론 (Conclusion)
비밀번호 노출 경고는 기술적 결함이 아닌 **보안 표준 미준수**에 대한 경고입니다. HTTPS로의 전환과 강력한 비밀번호 정책 수립은 현대적인 웹 개발자에게 필수적인 역량이며, 본 프로젝트에서는 이를 통해 실무 수준의 보안 인프라를 구축했습니다.
